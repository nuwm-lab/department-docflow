# Запуск на кафедрі

Покрокова інструкція для того, хто налаштовує розширення «Вхідна документація кафедри» для всієї кафедри (зазвичай — завкафедри). Займає близько години, з них більшість — встановлення в працівників.

Опис роботи розширення — у [README](../README.md), налаштування Google Cloud — у [oauth-setup.md](oauth-setup.md).

## Перед початком

- [ ] OAuth Client ID створено, розширення вже працює (перевірено на тестовій папці).
- [ ] Відомо, хто на кафедрі зберігатиме документи, а хто лише переглядатиме.
- [ ] Є право створити Спільний диск в університетському Google Workspace (або його вже створено).

## 1. Спільний диск і папка

Документи зберігаються на Спільному диску кафедри: тоді файли належать кафедрі, а не працівнику, і не зникнуть разом з його акаунтом.

1. Google Диск → **«Спільні диски»** → **«+ Новий»** → назва, наприклад «Кафедра — документи».
   Якщо кнопки «Новий» немає — створювати Спільні диски заборонено; попросіть адміністратора Workspace університету.
2. Відкрийте Спільний диск → **«+ Створити»** → **«Нова папка»** → **«Вхідна документація»**.
3. Скопіюйте посилання на папку «Вхідна документація» з адресного рядка — воно знадобиться працівникам.

Посилання має вести саме на папку «Вхідна документація», а не на корінь Спільного диска.

## 2. Права доступу

На Спільному диску ролі задаються учасникам диска (правою кнопкою по диску → **«Керувати учасниками»**) або окремо папці «Вхідна документація» (**«Поділитися»**).

| Хто | Роль | Що може |
| --- | --- | --- |
| Завкафедри | **Менеджер** | Усе, зокрема керувати учасниками й редагувати `_config.json` |
| Діловод | **Менеджер вмісту** | Зберігати документи, а також перейменовувати, переносити й видаляти помилково збережені |
| Уповноважені працівники | **Автор** | Зберігати документи (не можуть видаляти чужі файли) |
| Решта працівників | **Читач** | Переглядати документи й реєстр |

Розширення перевіряє права саме: користувач без права додавати файли отримає повідомлення «має лише перегляд папки» ще до будь-яких змін на Диску.

## 3. Спільні налаштування

1. Завантажте в папку «Вхідна документація» файл **`_config.json`** (підготовлений файл або [приклад](_config.example.json)).
2. Переконайтеся, що назва саме `_config.json` — без `(1)` чи `.txt`.

Підготовлений файл кафедри:

- типи документів — як у ТЗ: Наказ, Розпорядження, Вхідний лист, Службова записка, Протокол, Інше;
- правила: «Наказ», «Розпорядження», «Службова записка» («службова/доповідна записка»), «Протокол» — за словом у темі; «Вхідний лист» — усі листи з державних доменів `*.gov.ua` (МОН, міністерства тощо);
- `currentYearFolder` **не вказано**: папка навчального року (`2026-2027`) створюється автоматично, а 1 вересня розширення саме перейде на наступний рік — нічого змінювати щороку не потрібно.

Якщо треба зафіксувати рік вручну — додайте `"currentYearFolder": "2026-2027"` і створіть таку папку (див. README, «Перехід на новий навчальний рік»).

Правила можна доповнювати, коли стане зрозуміло, з яких адрес зазвичай надходять документи, наприклад:

```json
{ "type": "Наказ", "fromAddresses": ["kancelaria@nuwm.edu.ua"] }
```

Правила перевіряються згори донизу; спрацьовує перше, що підійшло. Зміни діють одразу для всіх — розширення читає `_config.json` під час кожного збереження.

## 4. Cloud-проєкт: запасні власники

OAuth-клієнт живе в Google Cloud-проєкті. Щоб розширення не залежало від однієї людини, додайте запасних власників ([oauth-setup.md](oauth-setup.md), крок 5):

- [ ] кафедральний акаунт — **Owner**;
- [ ] завкафедри — **Owner**;
- [ ] розробник — **Editor**.

## 5. Встановлення у працівників

Поки розширення не опубліковане в Chrome Web Store, кожен встановлює його вручну:

1. Отримати архів зібраного розширення (`dist`) і розпакувати в постійну папку (її не можна видаляти чи переносити).
2. Chrome → `chrome://extensions` → **«Режим розробника»** → **«Завантажити розпаковане розширення»** → вибрати розпаковану папку.
3. На сторінці налаштувань вставити посилання на папку «Вхідна документація» → **«Зберегти»**.
4. Відкрити будь-який лист у Gmail → іконка розширення → **«Увійти як …»** → дозволити.
5. Налаштування → **«Перевірити доступ»**:
   - у тих, хто зберігає, — «Можна зберігати документи»;
   - у читачів — «Право запису: лише перегляд» (так і має бути).

Порада: закріпіть іконку розширення на панелі Chrome (значок пазла → кнопка-шпилька).

## 6. Перший документ

1. Діловод зберігає перший справжній вхідний документ.
2. Переконайтеся, що з’явилися папка `2026-2027`, папка документа (лист, `.eml`, додатки) і «Реєстр вхідних документів 2026-2027».
3. Відкрийте реєстр з акаунта читача — документ має бути видно.

## Щорічно

Нічого: 1 вересня розширення саме почне зберігати в папку нового навчального року й створить новий реєстр. Листи кінця серпня, збережені вже у вересні, перевіряються на дублікати й у реєстрі попереднього року.

## Пізніше

- **Централізоване встановлення.** Через Google Admin Console розширення можна встановити всім примусово й одразу задати посилання на папку — тоді кроки 5.1–5.3 не потрібні (етап 2 за ТЗ).
- **Публікація.** Приватна публікація в Chrome Web Store для домену `nuwm.edu.ua` — без «Режиму розробника». Після публікації в OAuth-клієнт треба додати redirect URI з новим ID розширення ([oauth-setup.md](oauth-setup.md), розділ «Публікація в Chrome Web Store»).
