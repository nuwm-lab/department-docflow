# department-docflow

Розширення Google Chrome «Вхідна документація кафедри»: одним натисканням зберігає відкритий у Gmail вхідний документ (наказ, розпорядження, лист із додатками) у спільну папку кафедри на Google Диску та веде реєстр без дублікатів.

- Технічне завдання: [docs/TZ.md](docs/TZ.md)
- Налаштування доступу до Google: [docs/oauth-setup.md](docs/oauth-setup.md)
- Приклад спільних налаштувань: [docs/_config.example.json](docs/_config.example.json)

**Стан:** етап 1 (MVP) за ТЗ реалізовано. Правила класифікації та витягування номера й дати з етапу 2 також уже працюють.

## Як це працює

1. Відкрийте лист у Gmail і натисніть на іконку розширення.
2. Розширення читає лист і саме заповнює форму: тип документа, номер, дата, від кого, короткий зміст. Будь-яке поле можна змінити.
3. Натисніть **«Зберегти»**. На Диску з’явиться папка документа, а в реєстрі — новий рядок.

```
Вхідна документація/                         ← спільна папка кафедри
├── _config.json                             ← спільні налаштування (необов’язково)
└── 2026-2027/                               ← папка навчального року
    ├── Реєстр вхідних документів 2026-2027  ← Google Таблиця
    └── 2026-11-10_Наказ_№123-к_Про організацію навчального процесу/
        ├── Лист.md                          ← текст листа з метаданими (Markdown)
        ├── Оригінал.eml                     ← повна копія листа
        └── додатки в оригінальному форматі
```

Розширення не має власного сервера: дані йдуть лише між браузером і Google Workspace університету. Кожен працює під своїм акаунтом і зі своїми правами на папку.

## Встановлення

### Для адміністратора: один раз на кафедру

1. **OAuth Client ID.** Створіть Cloud-проєкт і клієнт за інструкцією [docs/oauth-setup.md](docs/oauth-setup.md) і впишіть Client ID у `public/manifest.json` (`oauth2.client_id`).
2. **Спільна папка.** Створіть папку «Вхідна документація», краще на Спільному диску кафедри, щоб файли належали кафедрі, а не особистому акаунту.
3. **Права доступу.** Надайте доступ до папки:

   | Роль | Право на папку |
   | --- | --- |
   | Діловод, уповноважені працівники | Редактор |
   | Решта працівників | Читач |
   | Завкафедри | Менеджер (на Спільному диску) або Редактор |

4. **Налаштування (необов’язково).** Покладіть у папку `_config.json` (див. нижче). Без нього діють значення за замовчуванням.

### Для кожного працівника

1. Отримайте папку `dist` (зібране розширення) від адміністратора або зберіть її самостійно (див. «Розробка»).
2. У Chrome відкрийте `chrome://extensions`, увімкніть **«Режим розробника»** (праворуч угорі).
3. **«Завантажити розпаковане розширення»** → виберіть папку `dist`.
4. Відкриється сторінка налаштувань: вставте посилання на папку «Вхідна документація» і натисніть «Зберегти».
5. Відкрийте будь-який лист у Gmail, натисніть на іконку розширення → **«Увійти як …»** і надайте дозволи.
6. На сторінці налаштувань натисніть **«Перевірити доступ»**: має бути «Можна зберігати документи».

ID розширення закріплено (`eglfhdbhakanbgheiobecjhjjdbjninp`), тож він однаковий на всіх комп’ютерах. Для робочого поширення ТЗ передбачає приватну публікацію в Chrome Web Store або примусове встановлення через Google Admin Console.

## Робота з розширенням

### Вікно збереження

| Поле | Звідки береться |
| --- | --- |
| Куди | Коренева папка + папка навчального року |
| Лист у ланцюжку | Якщо в ланцюжку кілька листів — за замовчуванням останній розгорнутий |
| Тип документа | Правила з `_config.json`; якщо жодне не спрацювало — «Інше» |
| № документа | «№ 123-к» у темі, назвах вкладень або тексті листа |
| Дата документа | «від 05.11.2026» або «від 5 листопада 2026 року» |
| Від кого | Ім’я відправника (або адреса); для пересланого листа — справжній відправник із блоку пересилання (Gmail, Outlook), з підказкою, хто переслав |
| Короткий зміст | Тема без «Re:/Fwd:», типу, номера й дати |
| Примітка | Вручну; потрапляє в `Лист.md` і реєстр |
| Додатки | Усі вкладення позначені; вбудовані зображення (логотипи в підписах) — ні |

Назва папки будується за шаблоном `{date}_{type}_№{number}_{summary}`, де дата — дата надходження листа. Без номера частина `№…` пропускається, недопустимі символи прибираються, зміст обрізається до 80 символів. Якщо така папка вже є, до назви додається `_2`, `_3`.

### Дублікати

- **Той самий лист** (збіг заголовка Message-ID): попередження «Вже збережено» з датою, автором і посиланням з’являється одразу, щойно відкрито вікно.
- **Ті самі вкладення в іншому листі** (збіг MD5): попередження з’являється після натискання «Зберегти».
- Пошук іде в реєстрі поточного й попереднього навчального року (листи кінця серпня).
- Зберегти повторно можна лише після галочки «Так, зберегти ще раз».

### Якщо щось пішло не так

- Рядок у реєстр додається **лише після** успішного завантаження всіх файлів.
- Якщо частина файлів не завантажилась, вікно покаже, які саме. Кнопка **«Повторити»** використає ту саму папку й докачає лише відсутні файли.
- Без права запису розширення повідомить про це ще до будь-яких змін на Диску.
- **Журнал операцій** (останні 50 збережень на цьому комп’ютері) — на сторінці налаштувань.

| Повідомлення | Що робити |
| --- | --- |
| «Відкрийте лист у Gmail» | Відкрийте конкретний лист, а не список «Вхідні» |
| «Оновіть вкладку Gmail (F5)» | Вкладку відкрили до встановлення чи оновлення розширення |
| «Папку … не знайдено або акаунт … не має до неї доступу» | Перевірте посилання в налаштуваннях і доступ до папки |
| «Акаунт … має лише перегляд папки» | Попросіть завкафедри надати права редагування |
| «Папку «2027-2028», вказану в _config.json, не знайдено» | Створіть папку року або виправте назву в `_config.json` |
| «Файл _config.json пошкоджено…» | Виправте JSON; у повідомленні вказано, що саме не так |

## Спільні налаштування `_config.json`

Файл лежить у кореневій папці й редагується адміністратором. Усі поля необов’язкові.

```json
{
  "currentYearFolder": "2026-2027",
  "documentTypes": ["Наказ", "Розпорядження", "Вхідний лист", "Службова записка", "Протокол", "Інше"],
  "rules": [
    { "type": "Наказ", "subjectContains": ["наказ"] },
    { "type": "Розпорядження", "subjectContains": ["розпорядження"] },
    { "type": "Вхідний лист", "fromDomains": ["mon.gov.ua"] }
  ],
  "folderNameTemplate": "{date}_{type}_№{number}_{summary}",
  "bodyFormat": "markdown",
  "alsoSavePdf": false,
  "checkPreviousYear": true
}
```

| Поле | Значення | За замовчуванням |
| --- | --- | --- |
| `currentYearFolder` | Назва папки поточного навчального року в кореневій папці | Визначається за датою (рік починається 1 вересня), папка створюється автоматично |
| `documentTypes` | Список типів для вибору; «Інше» додається завжди | Як у прикладі |
| `rules` | Правила визначення типу; спрацьовує перше, що підійшло | «Наказ» і «Розпорядження» за темою |
| `folderNameTemplate` | Шаблон назви папки: `{date}`, `{type}`, `{number}`, `{summary}` | Як у прикладі |
| `checkPreviousYear` | Шукати дублікати й у реєстрі попереднього року | `true` |
| `alsoSavePdf` | Додатково зберігати PDF листа (етап 2, ще не реалізовано) | `false` |

Умови правила (`rules`), регістр не важливий:

Для пересланих листів умови за відправником (`fromDomains`, `fromAddresses`) перевіряють справжнього відправника, а не того, хто переслав.

| Умова | Спрацьовує, якщо |
| --- | --- |
| `subjectContains` | Тема містить будь-яке зі слів |
| `bodyContains` | Текст листа містить будь-яке зі слів |
| `fromDomains` | Домен відправника збігається (зокрема піддомени: `mon.gov.ua` → `osvita.mon.gov.ua`) |
| `fromAddresses` | Адреса відправника збігається точно |

**Перехід на новий навчальний рік.** Створіть папку `2027-2028` у кореневій папці й змініть `currentYearFolder`. Наступне збереження піде в нову папку, де автоматично створиться новий реєстр. Якщо `currentYearFolder` не вказано, перехід відбувається сам 1 вересня.

Розширення попереджає про помилки в `_config.json` (невідомі поля, правила без умов, неправильні типи значень) на сторінці налаштувань («Перевірити доступ»).

## Реєстр

Google Таблиця «Реєстр вхідних документів РРРР-РРРР» у папці року створюється автоматично під час першого збереження.

| Колонка | Зміст |
| --- | --- |
| № | Порядковий номер (рахується формулою, тож правильний і при одночасному збереженні) |
| Дата надходження | Дата листа |
| Тип, № документа, Дата документа, Від кого, Короткий зміст | З форми збереження |
| Примітка | З форми збереження (доповнення до ТЗ) |
| Додатків | Кількість збережених вкладень |
| Папка | Назва папки документа з посиланням |
| Зберіг, Коли збережено | Пошта й час збереження |
| Message-ID, MD5 вкладень | Службові, приховані — для пошуку дублікатів |

Колонки можна переставляти й додавати власні: розширення знаходить службові колонки за назвою заголовка.

## Розробка

Потрібні Node.js (LTS) і npm.

```bash
npm install
npm run build      # збірка в dist/
npm test           # автотести (Vitest)
npm run typecheck  # перевірка типів TypeScript
```

Після `npm run build` натисніть ↻ на картці розширення в `chrome://extensions` і оновіть вкладку Gmail.

### Архітектура

Логіка побудована за схемою **«джерело → уніфікована модель документа → сховище»**: джерело (Gmail, а на етапі 3 — СЕД) перетворює свої дані в `SourceDocument`, а збереження на Диск і реєстр від джерела не залежать.

```
src/
├── manifest (public/manifest.json)
├── content/gmail.ts          content script: ID відкритого листа й пошта у вкладці (з DOM)
├── popup/                    вікно збереження: вхід, форма, прогрес, результат
├── options/                  налаштування: коренева папка, «Перевірити доступ», журнал
├── background/               service worker
│   ├── index.ts              обробка повідомлень від popup і options
│   ├── auth.ts               вхід у Google (launchWebAuthFlow) під поштою з вкладки
│   ├── workspace.ts          коренева папка → _config.json → папка року; перевірка доступу
│   ├── prepare.ts            лист + налаштування + попередня перевірка дубліката
│   ├── save.ts               збереження: файли, дублікати, реєстр, повтор після збою
│   └── api/                  Gmail, Drive (зокрема resumable upload), Sheets
├── sources/                  модель документа (types.ts) і розбір листа Gmail
├── classify/                 тип документа, № і дата, короткий зміст
├── storage/                  _config.json, навчальний рік, назва папки, Лист.md, реєстр
└── shared/                   типи повідомлень, налаштування, журнал, стилі
```

Модулі в `sources/`, `classify/` і `storage/` — чисті функції без звернень до мережі, покриті тестами (`*.test.ts` поруч із кодом).

### Важливі рішення

- **Вхід під поштою з вкладки Gmail**, а не профілю Chrome: `chrome.identity.launchWebAuthFlow` з `login_hint`. Тому OAuth-клієнт має тип «Web application». Токени зберігаються лише в пам’яті (`chrome.storage.session`) і оновлюються тихо.
- **ID листа береться з DOM** (`data-legacy-message-id`), бо формат URL Gmail не збігається з ID у Gmail API. Якщо Gmail змінить розмітку, правити треба [src/content/gmail.ts](src/content/gmail.ts).
- **Вкладення ідентифікуються за `partId`**: `attachmentId` у Gmail змінюється при кожному запиті листа.
- **`Лист.md` будується в popup**: Turndown потребує DOM, якого немає в service worker. Таблиці з листів (зокрема без рядка заголовків) конвертуються власним правилом.
- **Реєстр без формул, залежних від локалі**: посилання на папку вбудоване в текст клітинки, а не `=HYPERLINK(…)`. Текстові значення записуються з апострофом, щоб «1/09» не стало датою, а «=…» з теми — формулою.
- **Усі запити до Drive з `supportsAllDrives`**: папка може бути на Спільному диску.

### Ключ розширення

Поле `key` у `manifest.json` фіксує ID розширення. Приватна частина ключа (`.pem`) зберігається поза репозиторієм і потрібна лише для ручного пакування `.crx`. Не комітьте її.
